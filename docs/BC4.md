## 1. BC4 형식

### 1.1 블록 레이아웃

BC4 블록은 8바이트로, 4×4 텍셀의 **단일 채널**을 담는다.

```cpp
union
{
    struct
    {
        uint8_t red_0;
        uint8_t red_1;
        uint8_t indices[6];    // 16 × 3-bit
    };
    uint64_t data;
};
```

`[코드]` `DirectXTex/BC4BC5.cpp:82-91`

인덱스 접근은

```cpp
size_t GetIndex(size_t uOffset) const noexcept
{
    return static_cast<size_t>((data >> (3 * uOffset + 16)) & 0x07);
}
```

`[코드]` `BC4BC5.cpp:71-74`

즉 텍셀 $t$ 의 3비트 인덱스는 64비트 워드의 비트 $3t + 16$ 부터다.
텍셀 순서는 BC1 과 같은 행 우선이다: $t = 4\,\text{row} + \text{col}$.

$$
16 \text{ 텍셀} \times 3 \text{ 비트} = 48 \text{ 비트}, \qquad
\text{엔드포인트} = 16 \text{ 비트}, \qquad
\text{합} = 64 \text{ 비트}
$$

### 1.2 팔레트 — 두 가지 모드

```cpp
float DecodeFromIndex(size_t uIndex) const noexcept
{
    if (uIndex == 0) return float(red_0) / 255.0f;
    if (uIndex == 1) return float(red_1) / 255.0f;
    const float fred_0 = float(red_0) / 255.0f;
    const float fred_1 = float(red_1) / 255.0f;
    if (red_0 > red_1)
    {
        uIndex -= 1;
        return (fred_0 * float(7u - uIndex) + fred_1 * float(uIndex)) / 7.0f;
    }
    else
    {
        if (uIndex == 6) return 0.0f;
        if (uIndex == 7) return 1.0f;
        uIndex -= 1;
        return (fred_0 * float(5u - uIndex) + fred_1 * float(uIndex)) / 5.0f;
    }
}
```

`[코드]` `BC4BC5.cpp:47-68`

**6-interpolated 모드** ($r_0 > r_1$). 인덱스 $k$ 에 대해 $j := k-1$ 로 두면

$$
u_0 = \frac{r_0}{255}, \qquad
u_1 = \frac{r_1}{255}, \qquad
u_k = \frac{(7-j)\,r_0 + j\,r_1}{7 \cdot 255} \quad (k = 2 \dots 7,\ j = k-1 \in \{1..6\})
$$

**4-interpolated 모드** ($r_0 \le r_1$).

$$
u_k = \frac{(5-j)\,r_0 + j\,r_1}{5 \cdot 255} \quad (k = 2 \dots 5), \qquad
u_6 = 0, \qquad u_7 = 1
$$

$u_6, u_7$ 은 **엔드포인트와 무관한 절대값**이다.
BC1 의 3-color 모드에서 인덱스 3 이 투명 검정인 것과 정확히 같은 구조다.
`docs/BC1.md` §1.2 참조.

### 1.3 결정적 관찰 — 팔레트가 완전히 아핀이다

6-interp 모드에서 **8개 팔레트 값 전부**가 $(r_0, r_1)$ 의 아핀 결합이다.

$$
u_k = (1 - w_k)\frac{r_0}{255} + w_k \frac{r_1}{255},
\qquad
w_k = \frac{j_k}{7}
$$

| 인덱스 $k$ | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| $j_k = 7 w_k$ | 0 | **7** | 1 | 2 | 3 | 4 | 5 | 6 |

**유도.** $k=0$ 은 $u_0 = r_0/255$ 이므로 $w=0$, 즉 $j=0$.
$k=1$ 은 $u_1 = r_1/255$ 이므로 $w=1$, 즉 $j=7$.
$k \ge 2$ 는 정의에서 $j = k-1$. $\square$

$j_k$ 가 **0–7 범위의 정수 8개**라는 점이 §6 에서 결정적으로 쓰인다.

### 1.4 디코드가 float 이라는 점

BC1 은 팔레트를 **정수 코드 공간**에서 만든다
(`DividePaletteSumBy3`, `docs/BC1.md` §6.5).
BC4 는 그렇지 않다 — DirectXTex 의 레퍼런스 디코더는 float 로 계산하고
중간 반올림이 없다. `[코드]` `BC4BC5.cpp:53-58`

이것은 우리에게 **유리하다**. 팔레트 값이 정확한 유리수이므로
BC7 형식에서 필요했던 라운딩 보정항 $\varrho$ 가 아예 없다
(`docs/BC7.md` §3.1 참조).

> **주의.** 실제 GPU 하드웨어는 고정소수점으로 보간할 수 있다.
> D3D 사양은 결과가 UNORM 이라고만 규정한다.
> 여기서는 DirectXTex 소프트웨어 디코더를 레퍼런스로 삼는다 —
> BC1 구현이 `DividePaletteSumBy3` 로 DirectXTex 의 정수 팔레트를 정확히 재현한 것과
> 같은 원칙이다. `[설계]`

## 2. BC1 대비 쉬워지는 것과 어려워지는 것

### 2.1 쉬워지는 것

| 항목 | BC1 | BC4 | 근거 |
|---|---|---|---|
| 채널 수 | 3 | **1** | — |
| 주축 탐색 | 3×3 공분산 + 거듭제곱 반복 | **불필요** (1차원에 주축 개념이 없음) | §4.4 |
| 공분산 | 6성분 대칭 행렬 | **불필요** | §4.4 |
| 엔드포인트 정밀도 | RGB565 (5·6·5 비트) | **8비트 전정밀도** | `BC4BC5.cpp:86-87` |
| 엔드포인트 양자화 오차 (RMS) | R,B: $\approx 0.0093$ / G: $\approx 0.0046$ | **$\approx 0.0011$** | §5.4 |
| 팔레트 크기 | 4 | **8** (더 촘촘) | §1.2 |
| 전달 곡선 | sRGB LUT + `pow` | **없음** (BC4 에 SRGB 변종이 없음) | DXGI 포맷 목록 |
| 최근접 인덱스 | 4-way argmin | **닫힌 형태** (단조 램프) | §5.5 |
| 엔드포인트 순서 강제 | RGB565 패킹 비교 + LSB 조작 | 스칼라 비교 | §5.6 |
| BC5 | — | **BC4 두 번** | §7 |

**sRGB 가 없다는 점이 특히 크다.** BC1 에서 `LinearToSrgbBatch` 의
`XMVectorPow` 는 SSE2 빌드에서 스칼라 `powf` 4회 경로를 타고,
`[측정]` sRGB 인코드 시간의 약 58 % 를 차지했다 (`docs/BC1.md` §9.3).
BC4 에는 이 항이 통째로 없다.

### 2.2 어려워지는 것

| 항목 | 문제 |
|---|---|
| **3비트 인덱스 필드** | $16 \times 3 = 48$ 비트. 니블·바이트 어느 쪽에도 정렬되지 않는다. BC1 의 2비트 필드는 $16 \times 2 = 32$ 비트로 uint32 에 딱 맞고 니블 SWAR 이 자연스러웠다 (`docs/BC1.md` §6.3). BC4 는 그렇지 않다. |
| **팔레트 8개** | 히스토그램을 쓰면 빈이 4개가 아니라 8개다. → §4.3 에서 히스토그램을 쓰지 않는 것이 답임을 보인다. |
| **4-interp 모드의 비아핀 항목** | $u_6, u_7$ 이 절대값이라 심볼 형식이 깨진다. BC1 3-color 모드와 같은 방식으로 별도 처리해야 한다. |
| **float 팔레트** | 비트 일치 검증이 정수 산술만으로는 안 된다 (§1.4). 대신 유리수 산술로 정확히 다룰 수 있다 (§4.5). |

## 3. 기존 방식: DirectXTex BC4 파이프라인

비교 대상을 정확히 규정한다.

### 3.1 전체 경로

BC1 과 동일한 3단 구조다.

```
BC4 mip0 (.dds)
   │ ① 압축 해제         → R8_UNORM  mip0
   │ ② GenerateMipMaps    → 재귀 BOX, 레벨마다 8비트 재양자화
   │ ③ Compress           → 모든 레벨을 BC4 로 (mip 0 포함)
   ▼
BC4 mip0..mipN
```

②의 재귀성과 8비트 누적은 BC1 과 같은 코드다.

```cpp
const Image* src = mipChain.GetImage(level - 1, item, 0);   // ← 직전 레벨
```

`[코드]` `DirectXTexMipmaps.cpp:1036`

`[측정]` BC1 기준으로 이 누적은 mip 1 에서 58.93 dB, mip 12 에서 49.78 dB 로
**9 dB 열화**한다 (`docs/BC1.md` §2.2).
BC4 는 채널이 하나라 절대 오차는 다르겠지만 구조는 동일하다.

**한 가지 차이.** BC4 포맷에는 SRGB 변종이 없으므로
`IsSRGB(format)` 이 항상 거짓이고, 박스 평균은 저장값 공간에서 직접 수행된다.
BC4 데이터(러프니스, 하이트, AO, 노멀 성분)는 원래 선형 스칼라이므로 이것이 옳다.
BC1 에서 문제가 됐던 "감마 공간에서 필터링" 이슈
(`docs/BC1.md` §8.3 (나)) 가 BC4 에는 존재하지 않는다.

### 3.2 ③ 의 인코더

**엔드포인트 탐색** — 블록 min/max 를 구하고, 경계값이 있으면 4-interp 를 쓴다.

```cpp
const bool bUsing4BlockCodec = (MIN_NORM == fBlockMin || MAX_NORM == fBlockMax);
...
OptimizeAlpha<false>(&fStart, &fEnd, theTexelsU, 8);
auto iStart = static_cast<uint8_t>(fStart * 255.0f);
auto iEnd   = static_cast<uint8_t>(fEnd   * 255.0f);
```

`[코드]` `BC4BC5.cpp:209-224`

`OptimizeAlpha` 는 **좌표별 뉴턴법을 최대 8회** 반복한다.

```cpp
for (size_t iIteration = 0; iIteration < 8; iIteration++)
{
    ...
    if (d2X > 0.0f) fX -= dX / d2X;
    if (d2Y > 0.0f) fY -= dY / d2Y;
}
```

`[코드]` `DirectXTex/BC.h:235-299`

**여기에 두 가지 개선 여지가 있다.** `[설계]`

1. **좌표 하강이지 정확한 최소제곱 해가 아니다.**
   $\partial/\partial f_X$ 와 $\partial/\partial f_Y$ 를 독립적으로 갱신한다.
   두 엔드포인트는 상관되어 있으므로 2×2 정규방정식을 한 번에 푸는 것이 정확하다.
   BC1 구현은 이미 그렇게 한다 (`docs/BC1.md` §6.12).

2. **최종 양자화가 반올림이 아니라 절삭이다.**
   `static_cast<uint8_t>(fStart * 255.0f)` 는 **버림**이다.
   기대 오차가 $-0.5$ LSB 만큼 편향된다. 반올림하면 그 편향이 사라진다.
   `[코드]` `BC4BC5.cpp:218-219`

**인덱스 재배정** — 양자화된 엔드포인트로 팔레트를 다시 만들어 최근접을 고른다.

```cpp
float rGradient[8];
for (size_t i = 0; i < 8; ++i) rGradient[i] = pBC->DecodeFromIndex(i);
for (size_t i = 0; i < NUM_PIXELS_PER_BLOCK; ++i)
{
    ... 8-way linear scan for min |rGradient[uIndex] - theTexelsU[i]| ...
}
```

`[코드]` `BC4BC5.cpp:325-350`

이 부분은 우리 `PackAndReallocateSelectors` 와 같은 원칙이다.
다만 8회 선형 탐색인데, §5.5 에서 닫힌 형태로 대체할 수 있음을 보인다.

## 4. 수학적 기반

### 4.1 표기

- $u_k \in [0,1]$ : 팔레트 값 $k$, $k \in \{0,\dots,7\}$
- $s(t) \in \{0,\dots,7\}$ : 텍셀 $t$ 의 3비트 인덱스
- $j_k$ : §1.3 의 정수 가중치, $j = [0,7,1,2,3,4,5,6]$
- 사분면 $Q \subset \{0,\dots,15\}$, $|Q| = 4$

### 4.2 정리 1 — 사분면 평균

BC1 의 정리 1과 형태가 같다 (`docs/BC1.md` §4.2).

$$
\bar q \;=\; \frac{1}{4}\sum_{t \in Q} u_{s(t)}
\;=\; \frac{1}{4}\sum_{k=0}^{7} n_k\, u_k,
\qquad n_k = \bigl|\{\,t \in Q : s(t) = k\,\}\bigr|,\quad \sum_k n_k = 4
$$

빈이 4개에서 8개로 늘어난 것만 다르다.

### 4.3 정리 1′ — BC4 에서는 히스토그램을 쓰면 안 된다

**주장.** 6-interp 모드에서 사분면 평균은 **정수 하나**로 요약된다.

$$
\boxed{\;
\bar q \;=\; \frac{(28 - J_Q)\,r_0 \;+\; J_Q\,r_1}{7140},
\qquad
J_Q := \sum_{t \in Q} j_{s(t)} \;\in\; \mathbb{Z} \cap [0, 28]
\;}
$$

**유도.**

$$
\sum_{t \in Q} u_{s(t)}
= \sum_{t \in Q} \frac{(7 - j_{s(t)})\,r_0 + j_{s(t)}\,r_1}{7 \cdot 255}
= \frac{\bigl(7\cdot 4 - J_Q\bigr) r_0 + J_Q\, r_1}{7 \cdot 255}
$$

여기서 $\sum_{t \in Q} 7 = 28$ 을 썼다. 양변을 4로 나누면

$$
\bar q = \frac{(28 - J_Q) r_0 + J_Q r_1}{4 \cdot 7 \cdot 255} = \frac{(28 - J_Q) r_0 + J_Q r_1}{7140}
\qquad \square
$$

**범위 확인.** $j_k \le 7$ 이고 $|Q| = 4$ 이므로 $J_Q \le 28$. ✓

**왜 히스토그램보다 나은가.**

| | 히스토그램 경로 | 심볼 경로 (정리 1′) |
|---|---|---|
| 사분면당 상태 | 8개 카운트 | **정수 1개** ($J_Q$) |
| 평균 계산 | 8 MAC | **2 MAC** |
| 엔드포인트 의존성 | 팔레트 8값을 먼저 만들어야 함 | 마지막까지 미룰 수 있음 |

BC1 이 히스토그램을 쓰는 이유는 **카운트가 3채널에 공유되기 때문**이다 —
카운트 4개를 한 번 구해 R·G·B 세 번 재사용한다.
BC4 는 채널이 하나라 그 상각(amortization)이 없다.
따라서 **정보를 스칼라 하나로 접는 심볼 경로가 명백히 낫다.**

이것은 `docs/BC7.md` 의 통일 심볼 형식에서 $S = 1$, 채널 1개인 특수 케이스다.

$$
4 y_{j,c} = \sum_s\bigl[(n_{j,s}-\Sigma_{j,s})E_{0,s,c} + \Sigma_{j,s}E_{1,s,c}\bigr] + \varrho_{j,c}
\;\;\xrightarrow{\;S=1,\ c=1,\ \varrho=0\;}\;\;
4\bar q = (4 - \Sigma_Q)\frac{r_0}{255} + \Sigma_Q \frac{r_1}{255}
$$

$\Sigma_Q = J_Q/7$ 이다. $\varrho = 0$ 인 것은 §1.4 (float 디코드) 때문이다.

### 4.4 정리 2 — 분산은 필요 없다

BC1 은 주축을 찾기 위해 3×3 공분산과 거듭제곱 반복이 필요했다
(`docs/BC1.md` §4.3, §6.11).

**1차원에는 주축 개념이 없다.** 데이터가 직선 위에 있으므로 축은 그 직선 자체다.
따라서 BC4 인코더가 필요로 하는 통계량은

$$
y_{\min} = \min_i y_i, \qquad y_{\max} = \max_i y_i, \qquad
\sum_i y_i,\quad \sum_i w_i y_i,\quad \sum_i w_i,\quad \sum_i w_i^2
$$

뿐이다. 공분산 행렬, ANOVA 분해, 거듭제곱 반복이 전부 사라진다.

> **다만 블록 평균은 여전히 필요하다.** 평균 피라미드(정리 3)의 재료이기 때문이다.
> BC1 에서는 공분산 계산의 부산물로 공짜였는데
> (`docs/BC1.md` §6.10), BC4 에서는 명시적으로 구해야 한다.
> 비용은 사분면 평균 4개의 합 — 무시할 수준이다.

### 4.5 정확한 정수 산술이 가능하다

BC1 은 sRGB 전달 곡선 때문에 선형광 값이 무리수가 되어 float 이 불가피했다.
BC4 는 그렇지 않다.

**정수 자식 텍셀.** 정리 1′ 에서

$$
Y_Q := (28 - J_Q)\,r_0 + J_Q\,r_1 \;\in\; \mathbb{Z} \cap [0,\ 7140],
\qquad \bar q = \frac{Y_Q}{7140}
$$

$7140 < 2^{13}$ 이므로 $Y_Q$ 는 **uint16 에 들어간다.**

**정수 블록 합.**

$$
\tilde S_b := \sum_{q=0}^{3} Y_q \;\in\; \mathbb{Z}\cap[0,\ 28560],
\qquad \mu_b = \frac{\tilde S_b}{4 \cdot 7140} = \frac{\tilde S_b}{28560}
$$

역시 uint16.

**정수 평균 피라미드.** 레벨 $L$ 의 값을 "평균"이 아니라 "합"으로 유지하면
정확성이 끝까지 보존된다.

$$
\tilde S^{(L)}(x,y) = \sum_{j=0}^{1}\sum_{i=0}^{1} \tilde S^{(L-1)}(2x{+}i,\,2y{+}j),
\qquad
T_L = \frac{\tilde S^{(L)}}{28560 \cdot 4^{L-2}}
$$

비트폭은 레벨마다 2비트씩 자란다.

$$
\tilde S^{(L)} \le 28560 \cdot 4^{L-2}
$$

| 레벨 | 최댓값 | 필요 타입 |
|---|---|---|
| $L = 2$ | 28,560 | uint16 |
| $L = 6$ | 7,311,360 | uint32 |
| $L = 9$ | 468 M | uint32 |
| $L = 10$ | 1.87 G | uint32 (여유 있음) |
| $L = 11$ | 7.49 G | uint64 |

**권고.** `[설계]` 실용적으로는 float32 로 충분하다 —
상대 오차 $\sim 10^{-7}$ 은 8비트 출력 양자화($\sim 4\times10^{-3}$)보다
4자릿수 작다. 다만 **정확한 정수 경로가 존재한다는 것 자체가 BC1 에 없는 성질**이며,
비트 일치 검증이나 결정론적 재현이 필요할 때 쓸 수 있다.

### 4.6 정리 3 — Skip-level (BC1 과 동일)

블록 평균 이미지 $M$ 의 격자는 mip 2 의 텍셀 격자와 일치한다.

$$
M_{\text{width}} = \left\lceil \frac{W}{4} \right\rceil, \qquad
M_{\text{height}} = \left\lceil \frac{H}{4} \right\rceil
$$

그리고 박스 평균의 결합성으로

$$
T_L(x,y) = \frac{1}{4}\sum_{j=0}^{1}\sum_{i=0}^{1} T_{L-1}(2x{+}i,\ 2y{+}j),
\qquad T_2 \equiv M
$$

**유도와 의미는 `docs/BC1.md` §4.4 와 동일하다.** 핵심은

$$
\bigl\|T_L - \hat y_L\bigr\|^2 = (\text{레벨 } L \text{ 인코딩 오차만}), \qquad (\text{누적 항}) = 0
$$

BC4 에서는 §4.5 덕분에 이 등식이 **정수 산술로 정확히** 성립할 수 있다.
BC1 에서는 float 반올림이 미세하게 끼어든다.

### 4.7 4-interp 모드 입력의 처리

mip 0 에 4-interp 블록이 있으면 $u_6 = 0$, $u_7 = 1$ 이 아핀 형식을 깬다.
BC1 의 3-color 모드 처리와 같은 방식으로 항을 분리한다.

$$
4\bar q = \frac{(20\,m_Q - J'_Q)\,r_0 + J'_Q\,r_1}{5 \cdot 255} \;+\; n_{7,Q}
$$

여기서

- $m_Q$ = 사분면 안에서 아핀 인덱스($k \in \{0..5\}$)를 쓰는 텍셀 수
- $J'_Q = \sum_{t:\,k_t \le 5} j'_{k_t}$, $j' = [0,5,1,2,3,4,-,-]$
- $n_{6,Q}, n_{7,Q}$ = 인덱스 6, 7 의 개수, $m_Q + n_{6,Q} + n_{7,Q} = 4$
- 인덱스 6 은 값이 0 이므로 기여하지 않는다

**공통 분모로 통일하기.** 두 모드를 하나의 LUT 로 다루려면
분모 $\mathrm{lcm}(7,5) = 35$ 로 맞춘다.

$$
\hat j^{(6\text{-interp})} = 5 \cdot [0,7,1,2,3,4,5,6] = [0,35,5,10,15,20,25,30]
$$
$$
\hat j^{(4\text{-interp})} = 7 \cdot [0,5,1,2,3,4,\ast,\ast] = [0,35,7,14,21,28,\ast,\ast]
$$

두 표 모두 **엔트리가 8개이고 값이 0–35 인 바이트**다.
$\ast$ 로 표시한 두 자리는 별도 카운트로 처리한다.
$\hat J_Q \le 4 \times 35 = 140$ 이므로 여전히 int16 안이다.

`[설계]` **입력은 두 모드를 모두 읽어야 하지만, 출력은 6-interp 만 쓰면 된다** (§5.6).

## 5. 인코더 — 1차원이라 달라지는 것들

목표: 자식 텍셀 16개 $y_0,\dots,y_{15} \in [0,1]$ 이 주어졌을 때
$r_0, r_1 \in \{0,\dots,255\}$ 와 인덱스 16개를 정한다.

### 5.1 초기 엔드포인트 — PCA 없음

$$
a^{(0)} = \max_i y_i, \qquad b^{(0)} = \min_i y_i
$$

6-interp 모드는 $r_0 > r_1$ 을 요구하고 인덱스 0 이 $r_0$ 이므로,
**$r_0$ 가 큰 쪽**이다. BC1 의 거듭제곱 반복(`ComputeInitialEndpointsPCA`)이
min/max 리덕션 하나로 대체된다.

### 5.2 가중치 배정

선분을 $u(w) = a + w(b - a)$ 로 두면 ($w=0$ 이 인덱스 0, $w=1$ 이 인덱스 1)

$$
w_i = \frac{1}{7}\left\lfloor 7 \cdot \mathrm{clamp}\!\left(\frac{y_i - a}{b - a},\ 0,\ 1\right) \right\rceil
$$

BC1 의 `AccumulateLeastSquaresSample` 과 같은 식이며,
분모가 3 에서 7 로 바뀐 것뿐이다 (`docs/BC1.md` §6.12).

### 5.3 최소제곱 — 스칼라 2×2

$w_i$ 를 고정하고 $\sum_i (y_i - a - w_i d)^2$ 를 최소화한다.
$a$, $d$ 로 편미분해 0 으로 두면

$$
\begin{pmatrix} 16 & S_1 \\ S_1 & S_2 \end{pmatrix}
\begin{pmatrix} a \\ d \end{pmatrix}
=
\begin{pmatrix} \sum_i y_i \\ \sum_i w_i y_i \end{pmatrix},
\qquad
S_1 = \sum_i w_i, \quad S_2 = \sum_i w_i^2
$$

$$
\det = 16 S_2 - S_1^2, \qquad
a = \frac{S_2 \sum y_i - S_1 \sum w_i y_i}{\det}, \qquad
d = \frac{16 \sum w_i y_i - S_1 \sum y_i}{\det}
$$

BC1 과 **완전히 같은 식**이며 채널이 하나로 줄었을 뿐이다.
$\det < \varepsilon$ 이면 (모든 $w_i$ 가 같은 평탄 블록)
$a = b = \bar y$ 로 둔다.

**DirectXTex 대비.** `OptimizeAlpha` 는 $a$ 와 $d$ 를 독립적으로 갱신하는
좌표 하강이다 (`[코드]` `BC.h:294-297`).
위 식은 두 변수의 상관을 포함한 **정확한 해**다.
반복 없이 한 번에 최소점에 도달한다. `[설계]`

### 5.4 양자화 — 여기가 BC1 대비 가장 큰 이득

$$
r_0 = \bigl\lfloor 255\,a + 0.5 \bigr\rfloor, \qquad
r_1 = \bigl\lfloor 255\,(a + d) + 0.5 \bigr\rfloor
$$

**8비트 전정밀도**다. BC1 의 RGB565 와 비교하면

| 포맷 | 채널 | 레벨 수 | 스텝 | 균등분포 RMS 오차 $= \text{step}/\sqrt{12}$ |
|---|---|---|---|---|
| BC1 | R, B | 32 | $1/31 = 0.0323$ | 0.00932 |
| BC1 | G | 64 | $1/63 = 0.0159$ | 0.00459 |
| **BC4** | R | **256** | $1/255 = 0.00392$ | **0.00113** |

BC1 의 red/blue 대비 **약 8.2배 작다.**

여기에 팔레트 레벨도 4개에서 8개로 늘어나므로,
BC4 블록은 자기 입력을 BC1 보다 훨씬 정확히 재현한다.
이것이 §9 의 예측으로 이어진다.

> **DirectXTex 는 여기서 절삭을 쓴다** (`static_cast<uint8_t>`, `[코드]` `BC4BC5.cpp:218`).
> 반올림으로 바꾸면 기대 오차의 $-0.5$ LSB 편향이 제거된다.

### 5.5 인덱스 재배정 — 닫힌 형태

양자화된 엔드포인트로 팔레트를 다시 만든 뒤 최근접을 고른다.
BC1 과 같은 원칙이다 (`docs/BC1.md` §6.15).

**그런데 1차원에서는 8-way 비교가 필요 없다.**

6-interp 팔레트의 8개 값은 $r_1$ 에서 $r_0$ 까지의 **등간격 램프**를 이룬다.
램프 위치 $p \in \{0,\dots,7\}$ 를 "$r_1$ 에서 몇 칸 떨어졌는가"로 정의하면

$$
u = \frac{(7-p)\,r_1 + p\,r_0}{7 \cdot 255}
$$

이고, 목표 $y$ 에 가장 가까운 위치는

$$
p^\ast = \mathrm{clamp}\!\left(\left\lfloor 7\,\frac{255y - r_1}{r_0 - r_1} + 0.5 \right\rfloor,\ 0,\ 7\right)
$$

이다. 마지막으로 램프 위치를 BC4 인덱스로 되돌린다.

**유도.** §1.3 에서 인덱스 $k$ 의 가중치는 $w_k = j_k/7$ 이고
$u = (1-w)r_0 + w r_1$ 이므로, $r_1$ 로부터의 위치는 $p = 7(1 - w_k) = 7 - j_k$ 다.

| $p$ | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| $j = 7-p$ | 7 | 6 | 5 | 4 | 3 | 2 | 1 | 0 |
| **인덱스 $k$** | **1** | **7** | **6** | **5** | **4** | **3** | **2** | **0** |

($j=7 \Rightarrow k=1$, $j=0 \Rightarrow k=0$, 그 외 $k = j+1$) $\square$

즉 **곱셈 1회 + 반올림 + clamp + 8엔트리 LUT** 로 끝난다.
`pshufb` 한 번으로 16 텍셀을 동시에 처리할 수 있다.

DirectXTex 는 여기서 텍셀당 8회 선형 탐색을 한다
(`[코드]` `BC4BC5.cpp:339-347`) — 블록당 128회 비교다.

### 5.6 모드 선택

DirectXTex 는 휴리스틱을 쓴다.

```cpp
const bool bUsing4BlockCodec = (MIN_NORM == fBlockMin || MAX_NORM == fBlockMax);
```

`[코드]` `BC4BC5.cpp:209`

블록이 정확히 0 이나 1 을 포함하면 4-interp 를 쓴다.

**우리에게는 더 나은 선택지가 있다.** `[설계]`

밉 생성의 목표값은 **평균**이므로 정확한 0/1 은 그 영역 전체가 0 또는 1 일 때만 나온다.
그런 경우에도 6-interp 로 $r_0 = r_1 = v$ 를 쓰면 인덱스 0 이 $v$ 를 정확히 표현한다.
따라서 **출력은 항상 6-interp 로 두어도 손해가 없다.**

다만 1차원 인코딩은 매우 싸므로, **두 모드를 다 평가해 SSE 가 낮은 쪽을 고르는 것**이
가능하다. 비용은 2배지만 절대 비용이 작고, DirectXTex 의 휴리스틱보다 항상 같거나 낫다.

**엔드포인트 순서.** 6-interp 는 $r_0 > r_1$ 을 요구한다.
$r_0 = r_1$ 이면 자동으로 4-interp 로 해석되는데,
그 경우 인덱스 0 이 여전히 정확히 $v$ 를 주므로 **상수 블록은 어느 모드든 정확하다.**
BC1 의 `EnforceOpaqueEndpointOrder` 같은 LSB 조작이 필요 없다.

$d > 0$ 이 나오면 (초기값을 max/min 으로 잡으면 거의 없다)
두 엔드포인트를 교환하고 인덱스를 $p \mapsto 7-p$ 로 뒤집으면 된다.

## 6. SIMD 추출

BC1 의 `Count2x2Regions` 에 대응하는 부분이다 (`docs/BC1.md` §6.3).
여기가 BC4 에서 유일하게 더 까다로운 지점이다.

### 6.1 문제

64비트 블록 $B$ 에서 텍셀 $t$ 의 인덱스는 $(B \gg (3t+16)) \wedge 7$ 이다.
`[코드]` `BC4BC5.cpp:73`

$16 \times 3 = 48$ 비트는 니블에도 바이트에도 정렬되지 않는다.
BC1 의 2비트 필드가 uint32 에 정확히 16개 들어가 SWAR 이 자연스러웠던 것과 대조된다.

### 6.2 언팩 — 세 가지 방법

**(U1) AVX2 가변 시프트 — 권장** `[설계]`

$I = B \gg 16$ 의 48비트를 24비트씩 둘로 나눈다.
24비트 = 정확히 인덱스 8개다.

$$
I_{\text{lo}} = I \wedge \text{0xFFFFFF}, \qquad
I_{\text{hi}} = (I \gg 24) \wedge \text{0xFFFFFF}
$$

각각을 8개 uint32 레인에 브로드캐스트하고 레인별로 다른 양만큼 시프트한다.

```
shifts = [0, 3, 6, 9, 12, 15, 18, 21]
lanes  = _mm256_srlv_epi32(_mm256_set1_epi32(I_lo), shifts)
lanes  = _mm256_and_si256(lanes, _mm256_set1_epi32(7))
```

24비트가 uint32 안에 들어가므로 상위 시프트에서 잘리지 않는다.
두 절반을 바이트로 팩하면 16바이트 인덱스 벡터가 나온다.

명령 수: 브로드캐스트 2 + `vpsrlvd` 2 + AND 2 + 팩 ~3 = **약 9 명령**.

**(U2) 12비트 LUT — SSE2 대안** `[설계]`

$12 = 4 \times 3$ 이므로 12비트 그룹 하나가 인덱스 4개를 담는다.
48비트를 12비트씩 4조각으로 나누고, 각 조각을 4바이트로 펼치는 LUT 를 쓴다.

$$
\text{LUT}[\,0 \dots 4095\,] \to \text{uint32 (인덱스 4개를 바이트로 패킹)}
$$

크기는 $4096 \times 4\,\text{B} = 16\ \text{KB}$ 다. L1 에 상주할 만한 크기이고,
조회 4회로 16 텍셀이 나온다.

현재 코드베이스가 SSE2 베이스라인이므로
(`EnableEnhancedInstructionSet = StreamingSIMDExtensions2`,
`[코드]` `DirectXTex_Desktop_2022.vcxproj:139`)
AVX2 런타임 디스패치를 넣지 않는다면 이쪽이 현실적이다.

**(U3) 스칼라 16회** — 가장 단순. 시프트 + AND 16쌍. 폴백용.

### 6.3 사분면 합 — 4명령

인덱스 16바이트가 나오면 나머지는 BC1 보다 오히려 짧다.

**1단계 — 가중치 LUT (`pshufb` 1회)**

§1.3 의 $j$ 표는 엔트리 8개, 값 0–7 이다.
§4.7 의 공통 분모 버전을 쓰면 값이 0–35 이지만 여전히 바이트다.
`pshufb` 는 16엔트리 바이트 LUT 이므로 **한 명령으로 16 텍셀의 $j$ 값이 전부 나온다.**

```
jvec = _mm_shuffle_epi8(j_table, indices)      // 1 명령
```

BC1 의 $W$ 표가 4엔트리였던 것과 같은 원리이고,
BC7 의 $W^{(2)}, W^{(3)}, W^{(4)}$ 가 전부 16 이하라 `pshufb` 가 되는 것과도 같다
(`docs/BC7.md` §7.2).

**2단계 — 사분면 순서로 재배열 (`pshufb` 1회)**

사분면의 텍셀 집합은

$$
Q_0 = \{0,1,4,5\},\quad Q_1 = \{2,3,6,7\},\quad Q_2 = \{8,9,12,13\},\quad Q_3 = \{10,11,14,15\}
$$

이를 연속 4개씩 오도록 섞는다.

```
order = [0,1,4,5,  2,3,6,7,  8,9,12,13,  10,11,14,15]
r = _mm_shuffle_epi8(jvec, order)              // 1 명령
```

**3단계 — 쌍 합산 (`maddubs` 1회)**

```
p = _mm_maddubs_epi16(r, ones)                 // 1 명령
  = [j0+j1, j4+j5, j2+j3, j6+j7, j8+j9, j12+j13, j10+j11, j14+j15]
```

**4단계 — 사분면 합산 (`hadd` 1회)**

```
J = _mm_hadd_epi16(p, p)                       // 1 명령
  = [J_Q0, J_Q1, J_Q2, J_Q3, ...]
```

**정리.** 인덱스 벡터에서 사분면 심볼 4개까지 **4 명령**이다.

**오버플로 확인.**
공통 분모 버전에서 $j \le 35$ 이므로 쌍 합 $\le 70$, 사분면 합 $\le 140$.
`maddubs` 의 결과 int16 범위($\pm 32767$) 안이다. ✓
6-interp 전용 표($j \le 7$)를 쓰면 사분면 합 $\le 28$ 로 더 여유롭다. ✓

### 6.4 사분면 평균

정리 1′ 을 적용한다.

$$
\bar q_Q = \frac{(28 - J_Q)\,r_0 + J_Q\,r_1}{7140}
$$

사분면당 곱셈 2회 + 덧셈 1회. 4개 사분면이 int16 벡터 하나에 있으므로
SIMD 로 한 번에 처리된다.

### 6.5 BC1 과의 비용 비교

| | BC1 | BC4 |
|---|---|---|
| 인덱스 언팩 | 불필요 (2비트가 uint32 에 정렬) | **9 명령 (AVX2) 또는 LUT 4회** |
| 심볼 추출 | SWAR 8 명령 × selector 4개 = 32 | **4 명령** |
| 평균 계산 | 12 MAC/사분면 (3채널 × 4팔레트) | **2 MAC/사분면** |

`[미측정]` 총합은 실측이 필요하지만, 언팩 비용이 심볼 추출·평균 계산의
절감으로 상쇄될 것으로 보인다.

---

## 7. BC5 는 공짜다

BC5 블록은 **BC4 블록 두 개를 이어 붙인 것**이다.

```cpp
auto pBCR = reinterpret_cast<BC4_UNORM*>(pBC);
auto pBCG = reinterpret_cast<BC4_UNORM*>(pBC + sizeof(BC4_UNORM));
```

`[코드]` `BC4BC5.cpp:505-506`

- 바이트 0–7: red 채널 BC4 블록
- 바이트 8–15: green 채널 BC4 블록

두 채널이 **완전히 독립**이다. 공유하는 것이 없다.

따라서 BC5 지원은 BC4 파이프라인을 두 번 돌리는 것이며,
평균 이미지 $M$ 도 채널별로 하나씩 두면 된다.
`[설계]` 두 채널을 SIMD 레인에 나눠 담으면 사실상 추가 비용 없이 처리된다.

## 8. SNORM 변종

BC4_SNORM / BC5_SNORM 은 엔드포인트가 int8 이고 값 범위가 $[-1, 1]$ 이다.

```cpp
const int8_t sred_0 = (red_0 == -128) ? -127 : red_0;
const int8_t sred_1 = (red_1 == -128) ? -127 : red_1;
...
return (fred_0 * float(7u - uIndex) + fred_1 * float(uIndex)) / 7.0f;
```

`[코드]` `BC4BC5.cpp:105-127`

차이는 세 가지뿐이다.

1. **정규화 분모가 127** (255 가 아님)
2. **$-128$ 은 $-127$ 로 클램프**된다 (표현 가능한 최솟값이 $-127$)
3. 4-interp 모드의 절대값이 $0, 1$ 이 아니라 $-1, +1$ 이다

아핀 구조는 그대로이므로 정리 1′ 이 분모만 바꿔 성립한다.

$$
\bar q = \frac{(28 - J_Q)\,r_0 + J_Q\,r_1}{4 \cdot 7 \cdot 127}
$$

`[설계]` $-128 \to -127$ 클램프는 언팩 시점에 한 번 적용하면
이후 경로가 UNORM 과 동일해진다.
BC7 에서 회전을 언팩 시점에 흡수한 것과 같은 발상이다 (`docs/BC7.md` §3.3).

## 9. 예상 특성

전부 `[미측정]` 이다. BC1 실측값을 기준으로 방향만 예측한다.

### 9.1 품질 — 우리 방식의 핸디캡이 더 작을 것

`docs/BC1.md` §4.5 에서 정량화한 대로, 이 접근법의 구조적 핸디캡은
**mip 0 의 압축 오차를 물려받는 것**이다. BC1 실측:

```
mip 0   34.76 dB    ← mip0 BC1 오차를 100% 물려받음
mip 4   51.25 dB    ← 핸디캡 소멸
```

BC4 는 mip 0 을 훨씬 정확히 표현한다.

- 엔드포인트 양자화 오차가 **8.2배 작다** (§5.4)
- 팔레트 레벨이 4개가 아니라 **8개**
- 단일 채널이라 블록 내 색 분산 문제가 없다

따라서 mip 0 의 재구성 PSNR 이 BC1 보다 상당히 높을 것이고,
그만큼 **우리가 물려받는 초기 오차가 작다.**

`[예측]` BC1 에서 mip 1–2 에 나타난 약 $-0.2$ dB 핸디캡이
BC4 에서는 더 작을 것이다. 실측 필요.

### 9.2 속도 — sRGB 병목이 없다

BC1 `[측정]`:

| | 처리량 |
|---|---|
| BC1_UNORM_SRGB | 5.29 Mblocks/s |
| BC1_UNORM | 12.24 Mblocks/s |

sRGB 경로가 **2.31배 느리다.** 원인은 `XMVectorPow` 가 SSE2 빌드에서
스칼라 `powf` 4회 경로를 타는 것이고, 그것만으로 sRGB 인코드 시간의 약 58 % 였다
(`docs/BC1.md` §9.3).

**BC4 에는 이 항이 존재하지 않는다.** DXGI 에 BC4_UNORM_SRGB 가 없다.
따라서 BC4 는 BC1_UNORM 경로에 대응하는 속도 특성을 가질 것이다.

반면 3비트 언팩(§6.2)이 새 비용으로 추가된다.

### 9.3 E2E 속도향상 — BC1 과 비슷하거나 더 클 것

BC1 `[측정]` DDS 입력 E2E 4.31배. 그 대부분은
"압축 해제 + 전체 재인코딩"을 건너뛴 데서 나온다
(`docs/BC1.md` §9.2 — 밉 생성 커널 자체는 E2E 의 3.9 %).

BC4 도 같은 구조이므로 비슷한 배율이 예상된다.
DirectXTex 의 BC4 인코더가 블록당 최대 8회 뉴턴 반복 + 텍셀당 8회 선형 탐색을 하므로
(`[코드]` `BC.h:235`, `BC4BC5.cpp:339`), 재인코딩 비용이 상당하다.

### 9.4 요약 표

| 지표 | BC1 실측 | BC4 예측 | 근거 |
|---|---|---|---|
| mip 0 재구성 정확도 | 34.76 dB | **더 높음** | 8비트 엔드포인트, 8레벨 팔레트 |
| 우리 방식 핸디캡 (mip 1–2) | $-0.2$ dB | **더 작음** | 위 |
| sRGB 오버헤드 | 2.31× | **없음** | BC4 에 SRGB 변종 없음 |
| E2E 속도향상 | 4.31× | 비슷하거나 더 큼 | 베이스라인 인코더가 더 무거움 |
| 인코더 복잡도 | PCA + 3D LS | **1D LS 만** | §4.4 |

## 10. 구현 순서

`[설계]` 서로 독립적으로 착수 가능한 덩어리 셋이다.

### ① 언팩 + 심볼 추출

검증 기준: 심볼 경로로 재구성한 텍셀이 `D3DXDecodeBC4U` 와 일치할 것.
§4.5 의 정수 형식을 쓰면 **정확한 유리수 비교**가 가능하다.

순서:
1. 6-interp 모드만 (가장 단순, 완전 아핀)
2. 4-interp 모드 추가 (§4.7 의 절대값 항)
3. SNORM 추가 (§8, 분모와 클램프만 다름)

### ② 인코더

BC1 의 `OptimizeEndpointsLeastSquares` 를 1차원으로 축약하면 대부분 재사용된다
(`docs/BC1.md` §6.12). 새로 필요한 것은

- min/max 초기화 (PCA 대체)
- §5.5 의 닫힌 형태 인덱스 배정
- §5.6 의 모드 선택

### ③ 평균 피라미드

BC1 의 `DownsampleLinearMeanRow` 와 구조가 같다
(`docs/BC1.md` §6.17). 차이는

- 채널이 1개 (또는 BC5 면 2개)
- 전달 곡선 변환 없음
- 정수 경로 선택 가능 (§4.5)

**권고: ① → ③ → ② 순서.**
①과 ③만 되면 인코더 없이도 레벨 $\ge 2$ 의 타깃을 정확히 만들 수 있어
재귀 경로와 dB 비교가 가능하다 — 첫 정량 성과를 일찍 얻는다.
`docs/BC7.md` §10 과 같은 논리다.

### 11.1 BC1 에서 물려받는 것

| 항목 | 내용 |
|---|---|
| **비-2의 거듭제곱** | 정리 3(§4.6)의 동등성이 clamp-to-edge 때문에 깨진다. |
| **8n+1 크기** | 가로/세로가 8로 나눈 나머지 1이면 mip 1 이 $M$ 의 일부를 채우지 못한다. `docs/BC1.md` §11 참조. |
| **array / cubemap / volume** | texconv 통합이 2D 한 장만 처리한다. |

### 11.2 BC4 고유

**하드웨어 디코더와의 일치.**
DirectXTex 는 BC4 를 float 로 디코드한다(§1.4). 실제 GPU 는 고정소수점일 수 있다.
BC1 에서는 정수 팔레트를 정확히 재현해 이 문제가 없었지만,
BC4 에서는 레퍼런스 선택이 명시적 결정 사항이다. `[설계]`

**4-interp 절대값의 의미 손실.**
$u_6 = 0$, $u_7 = 1$ 은 "정확한 0/1"을 표현하기 위한 장치다.
평균을 취하면 그 정확성이 사라지므로, 마스크 텍스처처럼
0/1 이 의미를 갖는 데이터에서는 밉맵 자체가 의미를 잃는다.
이것은 밉맵 생성 방식의 문제가 아니라 데이터 성격의 문제다.

**노멀 맵 필터링.**
BC5 는 주로 탄젠트 공간 노멀 맵에 쓰인다 ($x, y$ 저장, $z = \sqrt{1-x^2-y^2}$ 복원).
$x, y$ 를 독립적으로 박스 평균하면 결과 벡터의 길이가 1보다 짧아지고,
재정규화하면 그 분산 정보가 버려진다.
분산을 러프니스로 옮기는 기법(Toksvig, LEAN mapping)이 정석이다.

**이것은 우리 방식의 한계가 아니다.** DirectXTex 의 박스 필터도 동일하게 동작한다
(`[코드]` `DirectXTexMipmaps.cpp:1067` `AVERAGE4`).
다만 압축 도메인에서 분산 정보를 얻는 것은 오히려 **쉽다** —
§4.3 의 심볼 $J_Q$ 와 원래 인덱스 분포가 블록 내 변동을 이미 담고 있다.
`[설계]` 이 방향은 추가 연구 가치가 있다.
